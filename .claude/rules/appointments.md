# Appointments

Loaded when working on appointments. Root context: `../../CLAUDE.md`.
Calendar *rendering* rules live in `lib/features/calendar/CLAUDE.md`.

## Times and status

- Snap appointment times to the quarter hour: `appointmentMinuteStep` (15, `calendar/domain/appointment_time_step.dart`) goes to `showAdaptiveTimePicker` → `CupertinoDatePicker.minuteInterval` on the four start/end pickers (add sheet, details edit body). Put a stored time through `snapToMinuteInterval` first — `CupertinoDatePicker` ASSERTS the initial minute is a multiple; it rounds to nearest but floors where rounding up would leave the day (23:53 → 23:45). The Material branch snaps on the way out (test harness only). Leave employee AVAILABILITY on the full minute wheel (interval defaults to 1) — working hours are not billed in quarters.
- Store only `pending` / `in_progress` / `done` / `cancelled` — `isValidAppointmentStatus` (`firestore.rules`) and `_allowedStatuses` (`firebase_appointments_repository.dart`); create with `status: 'pending'`. `confirmed` is retired; `done` reads "Complete". Account statuses (`active`/`invited`/`disabled`) live in `UserStatus` (`shared/widgets/feedback/user_status_chip.dart`), not `AppointmentStatus`. (ADR-0044)
- Never store or offer `AppointmentStatus.overdue`; it is display-only and time-derived. Don't add it to `appointmentValues` or the allowlist — `AppointmentStatus.overdue.raw` THROWS on purpose so a stray write fails at the source, not as an opaque `permission-denied`. (ADR-0044)
- Add clock-derived status rules ONLY to `AppointmentRecord.displayStatusAt(now)` (`appointment_record.dart`); `displayStatus` is `displayStatusAt(DateTime.now())` and `DashboardAggregator.displayStatusAt` delegates — never re-copy the ladder, a copy already drifted. Cards and the read-only header render `displayStatus`; the edit picker and every write seed from the stored `status`. (ADR-0044)
- Map a non-terminal visit to `in_progress` within [start, end] and `overdue` after `endTime`; a personal job never derives either (it returns its stored status, "Scheduled") — "job finished?" is the wrong prompt for a dentist appointment, not a missing way out (a personal block CAN be marked complete). Keep `selectOverdueCandidates` (`functions/notification_utils.js`) skipping `isPersonal` in step. (ADR-0044)
- Take "terminal" as raw strings only from `terminalStatusRawValues` (`calendar/domain/appointment_status_values.dart`, `{done, completed, cancelled}`, Material-free so `AppointmentRecord.isClosed` and History's `whereIn` share it); dropping the legacy `completed` alias made such docs invisible in History. `AppointmentStatus.isTerminal` mirrors it, pinned by `appointment_status_values_test.dart`. (ADR-0044)
- Normalize status through `AppointmentStatus.storedRaw(status)` on EVERY write that re-serializes a stored record or restores a status (the `event_details_controller` seed, `appointment_series_editor`'s `propagate`, the Siri snapshot builder, `replaceAssignee`, the mark-complete Undo), never `fromRaw(x).raw` — legacy `confirmed`/unknown docs are re-written verbatim and the rules reject the whole save; `storedRaw` maps legacy, unknown and `overdue` to `pending` without throwing. `UserStatus.fromRaw` is the account twin (unknown/empty → `invited`). (ADR-0044)

## Mark-complete and the action bar

- Offer "Mark as complete" on every open job with NO clock gate — `DetailsActionBar` checks only `!isDone && !isCancelled`, reads no clock, and `details_view_body.dart` derives no `now`. Don't reintroduce a start-time or "is today" test: the edit form's status picker is admin-only, so the button is a crew's only way to close a job. The rules never date-restricted an assignee's `status:'done'` (`appointment_employee_update_rules_test.dart`). (ADR-0045)
- Keep the assignee mark-done branch refusing only from `cancelled` (`firestore.rules`; `done`/`completed` → `done` is allowed) and pinning `updatedAt == request.time`; both client paths (`updateAppointmentStatus`, `updateAppointmentStatuses`) send `FieldValue.serverTimestamp()`, so a new status path that omits it is refused. (ADR-0045)
- Don't delegate `updateAppointmentStatus` to `updateAppointmentStatuses([id])`: the singular stamps `seriesOpId` only on `cancelled`, the plural's `WriteBatch` stamps it on EVERY status, which the `hasOnly(['status', 'updatedAt'])` branch refuses for a crew mark-done.
- Undo mark-complete only through the `restoreAppointmentStatus` callable (`functions/appointment_actions.js`), never a rules grant — no employee `allow update` disjunct can move a closed job back to open, and widening one would let an assignee reopen anything at any age. (ADR-0045)
- Keep the callable's checks: the doc is currently completed, the caller is admin or assigned (`mayRestore`), the target is `pending`/`in_progress`; it rate-limits 30/hour and deletes the server-owned `completedAt`, so an undo leaves no finish time on an open job. (ADR-0045)
- Gate admin actions with an explicit `showActions`: required on `showEventDetails(..., showActions:)`, defaulting CLOSED (`false`) on `EventDetailsSheet` / `EventDetailsView`. Pass the caller's resolved role and never re-add a `true` default — it showed employees Edit/Cancel/Delete that the rules then reject. Rules stay the real gate. (ADR-0046)
- On a DONE job, edit from `DetailsActionBar.onEdit` (the slot the inert "Complete" indicator held), and suppress `DetailsEditChip` in `DetailsViewBody`; `onEdit` is null-gated on `showActions`. Move the two together, or a finished job becomes uneditable. Cancelled and open jobs keep the top chip. (ADR-0046)
- Keep `AppointmentHistoryView`'s `isAdmin` flowing through `HistorySliverList` as `showActions` (defaulting closed; `HistoryScreen` passes `widget.isAdmin`) — History is where done jobs live, so hardcoding `false` hid the completed-job edit. (ADR-0046)
- Read a live admin gate from `isActiveAdminProvider` (`features/auth/application/`; `role == 'admin' && status == 'active'` off `currentUserDocProvider`), never a route argument's push-time `isAdmin`. It fails CLOSED while the doc is unsettled, errored or EMPTY; the empty-doc flicker for a real admin is ACCEPTED — holding the last answer needs a uid and drags Firebase auth into widget tests, so reopen the decision rather than file it as a bug. (ADR-0046)
- Resolve it ONCE per consumer and feed every gate there from that value: `DayRouteScreen` (`widget.isAdmin && ref.watch(...)` → crew picker, provider choice, `buildDayRoute`, `showActions` and `_prepareBuild`'s memo key, or the first cached `DayRoute` wins forever), the `AdminOnly` wrapper on `/history` (`app_routes.dart`, degrading to `InvalidRouteScreen`), `SettingsScreen._isAdmin` over `_isAdminArg`, `AppNavDrawer` (in `build`, one value for the admin groups, the header's role label and the calendar row's count query; the gate sits at the widget that feeds the pure `drawerGroups(isAdmin:)`, never in the catalog), and `DetailsViewBody._canRecordFieldWork`. (ADR-0046)
- Remember `_canRecordFieldWork` reads it as a NEGATIVE gate (`false` moves toward granting the compose box); it is safe only because `activeUserIdentityProvider.value` is also null in the unsettled window — don't remove or reorder that second check. (ADR-0046)
- Keep the `_tour` and `FeatureTourHost` of `DayRouteScreen` and `SettingsScreen` on the route argument, never the live gate — `TourSteps` owns GlobalKeys that must stay stable across rebuilds, and the one admin-only step is a `stepIf` on a widget that stops rendering anyway.

## Personal jobs and time off

- Offer the personal switch (`isPersonal`) on both add and edit, but on edit only when the job is already personal (`onPersonalChanged: null` otherwise), so a client visit can't be converted mid-life. Turning it on hides the client picker and drops `clientRequired` from `AppointmentFormValidator`; assignees STAY required — they are who the block is for. (ADR-0047)
- Write `clientId`/`clientName`/`clientPhone` as empty strings on both save paths of a personal job, so a hidden field never keeps a stale value. Never clear `controllers.address`: the address is OPTIONAL (`AppointmentAddressField.optional` → `AddressAutocompleteField`) and saved as `address.trim()`, since a supply run still happens somewhere; read surfaces already gate on `address.isNotEmpty`. (ADR-0047)
- Fall back to the **title** wherever a client name is spoken: the card and detail row say "Personal" (`calendar_personal`), the widget and Siri decoders fall back to `title`, and so do `_who` in `functions/notification_messages.js` (keep `_contextFor` passing `title`) and the separate `_who` in `live_activity_utils.js`, which is not optional — a timed personal job is still a travel candidate. (ADR-0047)
- Build every Live Activity `ctx` (for `startLiveActivity`/`updateLiveActivity`/`endLiveActivity`) with `liveActivityCtx(record, opts)` (`live_activity_utils.js`), never an object literal, and forward `title` through `_stateFor` into `buildContentState` — the builder field-picks its `ctx`, so a dropped field silently reads "Client". (ADR-0047)
- Drop the template chips, repeat picker, materials and photos from a personal job; an unnamed one saves as "Personal", substituted in the widget layer (where `l10n` lives). Turning personal on resets `repeat` in the ADD flow only — on edit, clearing it would rewrite a live series. `propagateClientEdits` can't reach personal jobs (empty `clientId`). (ADR-0047)
- Never count time off as a job, and always still show it: ask `AppointmentRecord.isTimeOff` (`isPersonal && isDayOff`), never the raw `isDayOff`, so a stray flag can't make a client visit vanish from tallies. (ADR-0047)
- Clear `isDayOff` in both controllers when personal goes OFF (the chip goes with the switch, so the flag would be unreachable), and copy it onto every sibling in `AppointmentSeriesEditor` (like `isAllDay`), or a holiday series counts as work from its second occurrence. (ADR-0047)
- Route every count through `countsAsWork` ("not cancelled, not time off", `appointment_day_slice.dart`) — `dottedJobsOn`, `_jobLabel`, `countsAsLoadOn` (`countsAsWork` plus `runsOn`, behind both the drawer badge and the roster's jobs-today) — and filter time off ONCE in `dashboardRecordsProvider`, so KPIs, workload, capacity and availability agree. The roster's "0 jobs today" above a "Day off" card is deliberate: a count answers how much work. (ADR-0047)
- Render time off through `AppointmentCard`'s `_DayOffStrip` and the detail `_DayOffBody` (no client, address, materials, photos or action bar) — inside the card so every surface gets it; layout rules live in `lib/features/calendar/CLAUDE.md`. Never make time off an `AppointmentStatus` member; it would force branches into `storedRaw`, the picker and the rules for a value nothing stores. (ADR-0047)
- Complete a day off by derivation only: the branch sits in `displayStatusAt` ABOVE the `isPersonal` early return. There is no Mark-complete or Cancel on one (delete it). Its stored status stays `pending` forever, so `purgeExpiredHistory` never purges it — accepted. (ADR-0047)
- Keep `_agendaOrder` and `isClosed` reading the stored status, clock-free, so a finished day off keeps date order instead of sinking into the closed block; the agenda's closed rule counts `closedJobCount` so the header and the rule can't disagree.
- Don't filter time off out of `findBusyEmployees` — booking time off is how someone reads as unavailable, and it is the permanent answer (no `timeOff` collection). The off-screen mirrors (push, widget, Siri, Live Activities) treat a day off as any personal block. (ADR-0047)

## All-day blocks

- Store an all-day block (`isAllDay`) as real instants, midnight → 23:59, so range queries, `orderBy('startTime')` and sweeps work unchanged; the flag only changes display ("All day" on `AppointmentCard` and the when-line). (ADR-0048)
- Resolve both save paths' instants through `appointmentSpan(...)` beside `allDaySpan` (`calendar/domain/policies/appointment_form_validator.dart`), never a hand-written ternary, or a change to the convention lands on one path only.
- Never clear `isAllDay` from `setPersonal(value: false)` — all-day is offered on EVERY job, so it is a deliberate choice. Keep the controllers asymmetric: `AddEventController` defaults it ON when personal turns on with no time picked (`add_event_controller_test.dart`); `EventDetailsController` never touches it in either direction (`event_details_controller_test.dart`), since an edit default would overwrite a choice. (ADR-0048)
- Keep the whole of "when" — all-day, date, start/end, repeat (a `SheetFieldRow` + `showAdaptiveActionSheet`) — in the schedule `SheetPanel`, all-day first; it hides the time rows. An all-day CLIENT job does go overdue after 23:59 — correct.
- Skip all-day records in `selectTravelCandidates` (`functions/travel_policy.js`) — there is no departure time, and the midnight start fired "time to leave" the night before. (ADR-0048)
- Carry `isAllDay` in `_contextFor` (`notification_messages.js`) so push text renders the date alone, and join `_whoAt` with "·" since no clock time follows. (ADR-0048)
- Put `isAllDay` in BOTH widget payload builders (`widget_sync_service.dart`, `widget_payload_utils.js`; Swift `Job` decodes `Bool?`, `timeLabel` says "All day"), filter "today" on `endTime`, and let `DaySchedule.nextJob` prefer a timed job, or a midnight block owns "up next" all day. (ADR-0048)
- Carry `isAllDay` and `title` in the Siri snapshot (`SiriStrings.who` is the one client→title→placeholder resolver; `timePhrase` speaks "all day"), and scope `nextAppointment`'s prefer-timed test (like the widget's `nextJob`) to the block's OWN span (`$0.start < earliest.end`), or today's all-day block is skipped whenever a later day has a timed job. `scheduleSnapshotVersion` (currently 4) is matched by `supportedVersions` in `ScheduleSnapshot.swift`. (ADR-0048)

## Multi-day span

- Allow up to `maxAppointmentSpanDays` (14) days, read as a DAILY WINDOW (9–5 means 9–5 each day); `isMultiDay` is derived, never stored. (ADR-0049)
- Keep `isValidAppointmentSpan` (`firestore.rules`, create + admin update) at 14 days inclusive PLUS two hours — CEL's `duration.value` is absolute while `combineDateAndTime` composes local wall-clock instants, so a fall-back week stores an extra hour; don't "simplify" the term away (`appointment_span_rules_test.dart`). The rules reach client writes only, so the app's clamp still contains console and Admin-SDK writes. (ADR-0049)
- Keep `appointmentSpanNotWidened`: an update of an already-oversized doc that doesn't widen it passes (same asymmetry as `emergencyFieldNotSet`), or the admin can't even cancel it. An assignee's status flip reaches neither guard.
- Derive day-scoping only from `AppointmentDaySlice` (`calendar/domain/appointment_day_slice.dart`): `sliceFor` / `expandToDays` / `lastWorkDayOf` / `lastWorkDayOfWindow` (the raw pair, for the booking-conflict dialog). Never re-derive a day index or run length at a call site. (ADR-0049)
- Keep `_windowsOf` (behind `dailyWindowsOverlap`) delegating to `expandRunWindows`, the one per-work-day loop — the windows a run is WRITTEN with and CHECKED against must be the same arithmetic, or DST/overnight changes surface as phantom or missed clashes. Let `dailyWindowsOverlap` compare ALL window pairs, never matching day indices, because an overnight window runs into the next calendar day. (ADR-0049)
- Name the last day the crew STARTS work as the end date (length `end − start + 1`); an end time at or before the start crosses midnight and counts nights, so there is deliberately no end-after-start validation (9:00–9:00 books 24 hours — accepted). Generate slices per WORK day, never per calendar day touched.
- Keep `AppointmentDateRange.fetchStart` (14 days back) a derived getter, never a constructor field — `==` keys on `start`/`end`, so equal days share one listener.
- Reserve "All day" for `isAllDay`; a timed middle day reads `9:00 AM – 5:00 PM · Day 3 of 5` and sorts in clock order — only all-day blocks pin above the day.
- Re-scope every range-stream consumer through `runsOn(appointment, day)` — the stream is a SUPERSET (everything started in the last 14 days); a reducer over `appointmentsInRangeProvider` without a day predicate is a bug. Test "today's window" on a multi-day run with the SLICE's window, not `startTime` (`computeTodayOps` carries `AppointmentDaySlice`s). (ADR-0049)
- Use `appointmentsInRangeProvider` (and `openCalendarRangeProvider`, published from it by `MainCalendarScreen`) for admins only and role-branch to `myAppointmentsProvider` elsewhere — it constrains `startTime` alone, so `isAssignedEmployee` rejects a technician's whole LIST query (copy the Siri snapshot and drawer badge).
- Apply the 14-day cap through ONE clamp, `_clampedDayCount`, for `sliceFor`/`runsOn`, `runsInRange`, `expandToDays` and `dailyWindowsOverlap` — a console write can exceed it. `AppointmentFormValidator` alone reads the raw count, because it must see an out-of-range value to refuse it. (ADR-0049)
- Take a form's run length from `runLengthDays` (beside `appointmentSpan`), never a hand copy in the form bodies.
- Change `functions/day_slice_utils.js` and `appointment_day_slice.dart` together; its jest cases reuse the Dart worked examples (Aug 1–5; Aug 1 22:00 → Aug 4 06:00 = 3 nights). It re-exports `MAX_APPOINTMENT_SPAN_DAYS` from `time_utils.js` and rebuilds windows as wall-clock times (not midnight + minutes, wrong on DST days). (ADR-0049)
- Treat a record with no `endTime` as single-day in `day_slice_utils.js` (the `hasWorkLeft` fallback) — read as equal times it would turn overnight, count to zero days and drop out of every mirror silently. (ADR-0049)
- Day-scope the mirrors (widget payload in Dart and JS, Siri snapshot, push date line): each carries THAT day's window, and the `dayIndex`/`dayCount` counter is omitted for a single-day job so older decoders parse. (ADR-0049)
- Leave the travel sweep (`startTime > now`, day 1 only) and overdue sweep (real `endTime`) unscoped. Withhold the Live Activity card from multi-day windows via the `dayCountOf(c) <= 1` start condition in `resolveReminderForAssignee` (`travel_utils.js`) — a four-day Lock Screen countdown is worse than no card; the day-1 `leaveNow` push still goes. (ADR-0049)

## Multi-day runs (one document per day)

- Split a multi-day JOB into N documents sharing `seriesId` (day 1's doc id) with stored `dayIndex`/`dayCount`; keep a personal block or time off ONE wide document — `AppointmentDaySlice` stays live for them. (ADR-0050)
- Keep the repeat picker hidden on a multi-day form — repeat and run sharing `seriesId` would make "this and the following" mean two things; repeating multi-day work needs a separate `runId`. (ADR-0050)
- Treat the stored pair as a LABEL only: `_dayIndexOn` stays purely derived and `sliceFor` substitutes the pair only into the slice it returns, only when the doc's own window is one day — feeding it to `runsOn` makes day 3 claim five more days on every badge. Mirrored by `storedRunLabel` (`functions/day_slice_utils.js`) with shared examples. (ADR-0050)
- Emit the pair from `toMap` only when `hasRunLabels` (`isRunMember` and 1 <= `dayIndex` <= `dayCount`) — a missing `dayIndex` parses to 0, which the rules refuse on every later edit, including the cancel. (ADR-0050)
- Select a run's scope by `dayIndex`, not `startTime`: pass the `anchor` to `futureSeriesRecords`/`futureSeriesIds` (`event_series_helpers.dart`) at EVERY run-scoped call site, `planPropagate` included. Derive the dialog count from `seriesOutlook`, built from that selection — a count is a promise about a write. (ADR-0050)
- Never let the EDIT form widen a client job (only ADD splits): `AppointmentFormFields.canSpanDays` gates the end-date row (`details_edit_body` passes `isPersonal || spanLength > 1`). (ADR-0050)
- Fix a run's LENGTH at booking (`AppointmentFormFields.isRunMember` → `AppointmentDateRows.showEndDate` hidden): shorten by cancelling the tail through the scope dialog, extend with a second booking — a reshape through `rewriteSeries` would recreate trailing docs and destroy per-day statuses and photos. (ADR-0050)
- Count and list a run as ONE job: `recountClientJobs` subtracts a `count()` over `dayIndex > 1` (`(clientId ASC, dayIndex ASC)` composite); `fetchClientHistory` filters `dayIndex <= 1` in DART, since a server inequality drops pre-field docs. Survivors of a this-day-only delete keep "of 5" — accepted. (ADR-0050)
- Never ask scope on mark-complete; edit, cancel and delete ask through `showSeriesScopeDialog` (`series_scope_dialog.dart`), and cancel writes through `updateAppointmentStatuses` (one batch, one shared `seriesOpId`, one push). Photos are per day (`images` is a per-document subcollection; no day-1 redirection). (ADR-0050)
- Keep day 1's doc id AS the `seriesId`: `diffAppointmentForNotifications` suppresses `assigned` for a created doc whose `seriesId` isn't its own id, which is the only reason a run notifies the crew once. The digest and overdue prompt speak per day — correct. (ADR-0050)
