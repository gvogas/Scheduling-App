## 2. Deviations — do NOT "fix" these back

Each of these is a decision with a reason. Reverting one re-introduces the bug
or the design violation it was made to avoid.

| # | Decision | Why |
| --- | --- | --- |
| 1 | `alwaysShowChip` was **dropped**, not ported | Every surviving call site passed `true`, and `pending` now renders as the neutral grey "Scheduled" chip rather than amber. A flag whose every call site passes the same value is dead config. |
| 2 | Cancelled dims to **0.6**, not the tile's 0.75 | The design specifies 0.6; 0.75 was pre-redesign. |
| 3 | The crew bar follows the **FIRST** assignee | `colorFromMap` returned null — and the card painted grey — for any job with more than one assignee. The design's `Theo +1` line makes the first assignee the card's identity. |
| 4 | The collapse spacer is **derived** (`gridHeight − stripHeight`), not the design's literal 150px | Our grid is taller than the mock's and scales with text; 150 visibly jumps the list at the moment of collapse. Derived height puts the first card at the same viewport position either side — the design's stated *intent*, met exactly. |
| 5 | Off-month cells render **faint numbers AND crew dots**, but stay untappable and out of semantics | The design says "blank, Ink 15, not tappable"; the program spec widened the fetch to ±14 days *specifically* so trailing days aren't dotless. Dots-plus-faint-number is the only reading that satisfies both. **Owner confirmed 2026-07-30 ("no blank").** |
| 6 | `showSeriesScopeDialog` **lost its Cupertino action-sheet branch** | The design puts a consequence line under each option; an action sheet cannot render one. A single design-mandated exception — every other adaptive surface keeps its Cupertino variant. |
| 7 | The calendar has **no `AppTopBar`**, so no "Calendar" title beside the Calendar pill | `AppTopBar` is a `PreferredSizeWidget` with a per-build fixed height and cannot host a week strip that rises in and out. **This settles open decision 5 from the P1 handoff.** |
| 8 | The month grid's **column width can fall below 48px on sub-360px phones**; the row pitch does not | A 7-column week cannot do better. The tap target is the row-height × column-width cell, and the circle inside it is 32px. |
| 9 | `FormSheetScaffold` was **not** migrated | Only the two appointment sheets moved to `FormSheetFrame`. The client and employee sheets keep it until P3/P4. Same reasoning leaves `InfoCard` untouched. |
| 10 | The Today control is a **pill, not a FAB** | `heroTag: 'todayFab'` is gone from the hub's tag list (already corrected in `.claude/rules/frontend.md`). |
| 11 | The header title uses **`headlineLarge`**, not the plan's `headlineMedium` | The plan said to verify against the ramp rather than trust the name. The design's 22/700/−0.025em step is `headlineLarge`; `headlineMedium` is 19px. The same check made the calendar month label `displayLarge` (26px), not `displaySmall` (19px). |
| 12 | The detail sheet **kept the repeat indicator** | The plan dropped it with the date/time rows. A read-only sheet that no longer says a visit recurs has lost real information, so it survives as a tertiary line under the when-line. |
| 13 | **C2 converted three picker fields to `SheetFieldRow`, not the plan's six** | Date, start and end had a real picker behind a `readOnly` TextField and converted cleanly. Client and address did not: `ClientSearchField` owns debounced search, a results dropdown, inline add-client and its own clear button, and `AppointmentAddressField` owns the client-vs-custom toggle. The plan calls them "a `SheetFieldRow` opening the existing picker", but there is no picker to open — the search **is** the field. Converting them means rebuilding two working interactions, not restyling them. **This is the one piece of P2 a later session could legitimately finish**; treat it as new work, not as a fix. |
| 14 | `assignee_names.dart` (`resolveAssigneeNames`) was **deleted** | Not in the plan. `crewFor` left it with zero production callers, so it went with `AppointmentTile` rather than lingering as dead code with a live test suite. |

## 3. Bugs found while building — the non-obvious failure modes here

1. **`jumpToPage` inside `didUpdateWidget` crashes the framework** (`'!_dirty': is not true`).
   `CalendarMonthPager` defers it to a post-frame callback that **re-reads
   `widget.month`** rather than capturing a target, so a burst of changes settles
   on the latest one.
2. **A `PageView` echoes programmatic jumps back through `onPageChanged`.**
   `jumpToPage` fires it exactly like a swipe, so a picker-driven month change
   round-tripped and reset the focused day to the 1st. `onPageChanged` ignores a
   page that already matches `widget.month`. Keep that guard.
3. **The collapse re-arm direction is easy to get backwards.** "Arms once the
   user has scrolled past 44px" means the offset dropping **below** 44 on the way
   back up. Reading it the other way makes a scroll-to-top never re-expand.
4. **The ±14 overscan is asymmetric in origin, symmetric in value.** Max lead is
   6 days (a month starting the day before the week start); max trail is 14 (a
   28-day February starting *on* it). February needs no lead at all.
5. **The header's title and controls cannot share one row at large text.** The
   Calendar pill's label grows unbounded — at 2× the row overflowed by 138px.
   `AppHeaderPair` has no internal width cap and is shared by every screen, so do
   **not** fix it there; the header block folds under `context.isCompact`.
6. **A lazily-built `FadeInItem` leaves a pending timer.** Now that the agenda is
   a sliver, scrolling builds rows late and their 30ms-per-row stagger is still
   pending at teardown → "A Timer is still pending after the widget tree was
   disposed". Any new scrolling test on this screen needs a drain pump
   (`await tester.pump(const Duration(milliseconds: 300))`).
7. **`FormSheetFrame` IS a sheet.** The edit body was nested inside
   `DraggableSheetFrame`, so it could not wrap itself — the chrome switch had to
   move up into `EventDetailsSheet`, which watches `isEditing`. Nesting two
   draggable sheets is the failure this avoids.
8. **A showcase target cannot be a sliver.** `_tourStep` wraps a box widget, and
   the agenda became a sliver in A5, so the `calendarDayList` step moved onto
   `AgendaHeader` (which is why that is a public widget).

## 4. Invariants P2 established

All are now recorded in `CLAUDE.md` / `.claude/rules/frontend.md`; this is the
short list of what a later session must not undo.

- ~~`visibleMonth` overscans **±14 days** because the grid is 42 cells.~~
  **Revised 2026-07-31:** the grid is 4–6 rows, so ±14 is now a deliberate
  superset rather than exact cover — keep it anyway, and use
  `AppointmentDateRange.forCalendar` (month ∪ selected day), not `visibleMonth`,
  as the screen's range.
- `today` comes from `currentDayProvider`, never `DateTime.now()`.
- **Collapse is portrait-only.** `_splitCalendar` short-circuits the strip.
  **Revised 2026-07-31:** there is no scroll listener any more — collapse is a
  drag on the divider — so the TickerMode caveat is moot.
- `AppointmentCard` uses `IntrinsicHeight`, so **nothing in its subtree may use
  `LayoutBuilder`, `AutoSizeText` or `FittedBox`**.
- **`findBusyEmployees` must exclude the appointment under edit** — by doc id,
  not by series. A clash returns the sealed `EventDetailsBusyEmployees` and
  **must clear `isSaving`** before returning.
- A destructive filled button reads `palette.dangerFill`, never `scheme.error`.
  The old scope dialog violated this; it is fixed.
