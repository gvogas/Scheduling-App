## 4. What P1 hands P2

P2 is the calendar grid, appointment card, sheets and forms. It builds on these, all landed:

**Tokens** (`lib/core/theme/design_tokens.dart`) — placement rule: *a role goes on `ColorScheme`
iff Material's own widgets read that slot implicitly; everything else goes on a `ThemeExtension`.*
Four extensions are registered on both themes:

- `theme.palette` (`AppPalette`) — every role Material has no slot for. `primaryAccent` (text/icon
  blue, vs `scheme.primary` = **fill** blue), `dangerFill`/`onDangerFill` (destructive fill, vs
  `scheme.error` = lifted **foreground** red), `textBody`/`textTertiary`/`textMuted`/`textFaint`,
  `sheetRow`, `lockedPanel`, `track`, `barTint`, `heroGradient`, the four notice dots.
- `theme.monoType` (`AppMonoType`) — 10 named mono styles. A call site writes
  `theme.monoType.data` / `.metric` / `.label` / `.numeralHero` / `.numeralKpi` / `.numeralSection`
  / `.numeralSub` / `.groupLabel` / `.fieldLabel` / `.micro`. **Never a raw `fontFamily`.**
- `theme.statusColors` (`AppStatusColors`) — now +3 neutral fields (`neutralContainer`,
  `onNeutralContainer`, `onNeutralContainerMuted`) backing the Scheduled/Cancelled chips.
- `theme.cardStyle` (`AppCardStyle`) — now +8 shadow sets: `sheetShadow`, `dialogShadow`,
  `drawerShadow`, `noticeShadow`, `fabShadow`, `pillShadow`, `thumbShadow`, `knobShadow`.

Role radii exist on `AppRadius` (`rCard` 15, `rPanel` 18, `rHero` 20, `rSheet` 26, `rDialog` 22,
`rFab` 20, `rIcon`/`rInput` 12, `rThumb` 9, `rRow` 13, `rSwatch` 12) — the numeric names keep
their true values, so **P2 migrates call sites onto the role names**. `AppMotion` gained
`emphasized`, `popIn`, `drawer`, `riseIn`, `riseInShort`, `dropdownSheet`, `noticeCycle`, and
`sheetStyle` was revalued to 300/240 ms.

**Crew colour** — `crewColorOf(theme, storedArgb)` resolves a **stored light ARGB int** to what
this theme renders; `avatarForegroundFor(theme, background)` picks its foreground. Never store a
lifted value. `AppColors.crewPalette` is the 10 assignable hues.

**Navigation** (`lib/core/navigation/`) — sealed `AppDestination` = `HubTab` (4 IndexedStack
panes) + `PushedDestination` (4 plain routes). `navigateToDestination` is the one nav action;
`goHomeToCalendar` is the one go-home gesture.

**Chrome** — `AppHeaderPair` in every `AppTopBar.actions`, `AppNavDrawer` as every screen's
`endDrawer`, and the notice is a dark status-dot pill on `scheme.inverseSurface`.

### Things P2 will visibly inherit

- **`labelLarge` grew 11 → 14px.** Any call site using it as a *small* label renders bigger than
  before. P2–P7 correct these as they sweep screens — this is expected, not a regression.
- **Card title 15.5 folded into `titleMedium` 15.** If P2 insists on 15.5, `AppointmentCard` does
  a local `copyWith(fontSize: 15.5)`.
- **`day_route_screen.dart` and `staff_marker_icon.dart` still call `contrastingForegroundFor`
  directly.** They compile fine; dark map pins just show unresolved crew colours until their own
  project migrates them to `crewColorOf` + `avatarForegroundFor`.

## 5. Invariants P1 established — don't undo them

1. **`select(settings)` must stay a compile error.** That is the entire point of the sealed split.
   Never collapse it back to one enum plus a list or an `isHubTab` flag.
2. **A destination's `.name` is load-bearing** — it is the persisted `tour_seen_tabs` key AND the
   showcase scope name. Renaming a member silently replays or orphans a tour. (That is why the
   member stayed `employees` while its label became "Team" via `nav_team`.)
3. **`_popToShell` targets the shell's captured `ModalRoute`, never `isFirst`.** On `_hubRoute`'s
   fallback branch the shell is not route #1, so `popUntil(isFirst)` pops the shell itself.
4. **`FeatureTourHost`'s gate is chosen by the destination's sealed type**, not by a null
   `HubShellScope` — a null scope also describes a hub screen hosted standalone in a test, where
   "never start" must be preserved.
5. **A closed drawer's child is never built**, so watching `.autoDispose` count providers in
   `AppNavDrawer` is free. Do **not** add an "is open" flag or `onEndDrawerChanged` hook.
6. **No screen needs a `GlobalKey<ScaffoldState>`** — `AppHeaderPair` resolves its host via
   `Scaffold.of(context)`. Both hand-rolled keys were deleted; don't reintroduce one.
7. **A destructive filled button reads `palette.dangerFill`, never `scheme.error`** — in dark,
   `scheme.error` is the lifted foreground red and is unusable as a white-text fill.
8. **`_hubRoute` + `HubTabRedirectRoute` survive** at three tab routes. They look like dead code
   but remain the cold-start fallback and are pinned by `hub_shell_test.dart`. Don't delete.
9. **The drawer sits *below* modal sheets, not above them.** Accepted, not a bug: Flutter's end
   drawer lives inside its `Scaffold`, so any modal route paints over it. Only the notice — which
   rides the Navigator's overlay via `navigatorKey` — is genuinely on top. Do **not** rebuild the
   drawer as a route to "fix" the ordering; that breaks `Scaffold.of(context).openEndDrawer()` and
   the local-history-entry back behaviour the design depends on.
10. **`AppTopBar`'s `compact == context.isLandscape` assert stays.** Every call site must keep
    passing `compact: context.isLandscape` or the assert fires in debug.

## 6. Deviations from the written plan — already in the code, don't "fix" them back

**Phase A**

1. **`AppMonoType.light`/`.dark` are `static final`, not `static const`.** The plan's
   `const AppMonoType _monoFor({...}) => ...` does not compile — Dart has no const *functions*. A
   const named constructor also fails: a const initializer may not construct an object
   (`TextStyle(color: ink)`) from a *parameter*, only from a constant. So `AppMonoType._of` is a
   plain constructor, and the `ThemeData(extensions: [...])` lists are **non-const**. Restoring
   `const` would mean duplicating all ten styles per theme.
2. **A3 also retargeted every component theme** (inputs, buttons, dividers, sheets, drawer, FAB)
   off the legacy `AppColors.*` names, because A5 Step 2 expects zero stragglers. It found zero.
3. **Fixed a latent overflow in `employee_details_view.dart`** — `_ColorRow`'s `Column` was not
   wrapped in `Expanded` (unlike its `_DetailField` sibling), so the larger `labelSmall` (9 → 11px)
   overflowed by 48px at 2× text on a 320px viewport. The row now mirrors `_DetailField`.
4. `test/employee_color_grid_test.dart` seeds from `AppColors.crewPalette` — `employeePalette` is
   gone.
5. `status_pending` was already "Scheduled"/"Planifié" in both ARBs — A4 Step 4 verified, no edit.

**Phase B**

6. **`test/features/settings/replay_tour_row_test.dart` swapped `pumpAndSettle` for six 500 ms
   pumps.** Settings is a pushed route now, so clearing the seen flags immediately restarts its
   tour and the showcase overlay animates continuously — `pumpAndSettle` timed out, and too short
   a pump tore the harness down mid auto-scroll (showcaseview then touched a defunct `State`). The
   assertion is unchanged.
7. **`test/routes/hub_shell_test.dart` substituted tabs** per B2 Step 6: the `.settings` case
   became `HubTab.liveMap`, the `.history` case became `HubTab.employees`.

**Phase C**

8. **`AppHeaderBackButton` was dropped.** C1 specified it, but `AppTopBar`'s existing leading is
   `AppBackButton`, which already renders a Cupertino variant on iOS and has its own adaptive test.
   A second, simpler back button would have been duplicate code that *regressed* iOS adaptivity.
9. **The calendar keeps its Day-route action button** beside the pair. The plan's shorthand was
   `actions: const [AppHeaderPair()]`, but that button is the `TourStepId.calendarDayRoute` target;
   removing it would have silently dropped a step from the calendar tour.
10. **`TextSizeScreen` gained `isAdmin`/`employeeId`.** It had no identity args, and a drawer
    without them renders the wrong rows. Its only push site (Settings) supplies them.
11. **C2's `SettingsDrawer` deletion was merged into C3's `endDrawer` swap**, so every commit
    compiles. The plan implied a broken intermediate; there was none.
12. **A modal sheet over a pushed screen dismisses a running tour and marks it seen** — inherited
    deliberately from the existing mid-tour tab-switch policy, not a new regression.
13. **Drawer re-tap of the current pushed screen is a no-op** (the `ModalRoute.settingsOf` guard).
    New, correct behaviour.

## 7. Verified facts — don't re-derive

- Flutter **3.44.1**. `ModalRoute.settingsOf`, `getInheritedWidgetOfExactType`,
  `MediaQuery.accessibleNavigationOf` and `ModalRoute.of` all exist (checked in the SDK source).
- **A closed drawer's child is never built** — `_DrawerControllerState._buildDrawer` returns
  `SizedBox.shrink()` (or a bare drag-detector) while `_controller.isDismissed`. A recon agent
  claimed the opposite; it was wrong.
- Instrument Sans on Google Fonts is **variable-only**; the statics come from the upstream
  `Instrument/instrument-sans` repo at `fonts/ttf/`. fontsource ships only woff/woff2.
- **Derived dark values still wanting designer sign-off** (the design handoff omitted dark
  counterparts): body text `#C5D0E2`, amber chip fill `0x29F1A83C`, track `0x14FFFFFF`, bar tint
  `#31445F`, locked panel `#121B2A`, blue-tint pressed `0x334B90F7`, `onError` `#1C060A`, the
  brown/olive crew hues and their lifts, and the 150° gradient approximated as
  `Alignment(-0.5,-1) → Alignment(0.5,1)`.
