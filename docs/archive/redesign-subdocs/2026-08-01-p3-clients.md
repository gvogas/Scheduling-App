# P3 — Clients Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task.
> Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the redesigned Clients surface — seven new model fields with matching rules
caps, archive-instead-of-delete, a fast New-client sheet and a full Edit sheet on the P2 form
chrome, a restyled read-only detail page, and a server-maintained `jobCount`.

**Architecture:** The archived flag is filtered **in Dart, never in a Firestore `where`**
(pre-existing docs lack the field and Firestore excludes docs missing a filter field). That
forces one structural change: `fetchClientsPage` stops returning a bare `List` and returns a
page object carrying the RAW server-page size and the RAW cursor separately from the filtered
items — without it, one archived doc in a page permanently truncates the list. `jobCount` is
maintained by an absolute `count()` recount in a new retry-safe appointment trigger, never by
`FieldValue.increment`. The sheets adopt P2's `FormSheetFrame` / `SheetPanel` / `KeyValuePanel`
chrome, retiring `FormSheetScaffold` and `InfoCard` from the clients feature.

**Tech Stack:** Flutter 3.10.7 / Dart, Riverpod 3, Freezed, `infinite_scroll_pagination`,
Firebase (Firestore, Cloud Functions v2 on Node), `gen_l10n`.

## Global Constraints

Every task's requirements implicitly include this section.

- **Baseline to hold:** `flutter analyze` → **0 issues**, `flutter test` → **1202 passing**
  (2026-08-01). Every task ends green on both. `cd functions && npm run lint` (80-char limit)
  and `npm test` for any task touching `functions/`.
- **No `where('archived', ...)` anywhere.** Pre-existing and Wave-imported docs lack the field
  and Firestore excludes docs missing a filter field. The test is always `!(archived ?? false)`.
- **`toMap` must NEVER emit `waveCustomerId`, `wave`, or `jobCount`** — all function-owned and
  rejected by `firestore.rules`.
- **Every new client-writable field gets its type/length cap in `isValidClientData` in the same
  commit**, and the caps must be applied to `allow create` as well as `allow update`.
- **Localisation:** every new string is a paired EN + FR key in `lib/l10n/app_en.arb` and
  `lib/l10n/app_fr.arb`, EN carrying an `@key` block (description + typed placeholders) —
  `required-resource-attributes: true` fails the build on a bare key. Key prefix `clients_`.
  A hook regenerates `flutter gen-l10n` on ARB edits; do not run it by hand.
- **Offline fail-fast:** every new write surface checks `ref.read(isOfflineProvider)` and
  returns a fabricated `SocketException('offline')` **before** setting the in-flight flag.
- **Submit reentrancy:** set the in-flight flag synchronously BEFORE the first `await`; reset it
  on every early return and `catch`.
- **Touch targets ≥ 48×48** regardless of the design's visual sizes. **No hardcoded status-bar
  or home-indicator insets** — use `MediaQuery.paddingOf(context)` / `SafeArea`.
- **Design px are 1.0-scale minimums** — nothing fixed-height that holds scaled text.
- **Never branch on `isDark`/brightness** for styling; read `theme.palette` / `theme.statusColors`
  / `theme.cardStyle`. Success is `theme.statusColors.success`, never `tertiary`. A destructive
  filled button reads `palette.dangerFill`, never `scheme.error`.
- **Notices, not SnackBars:** `ref.read(noticeServiceProvider).success/error(...)`. Generic catch
  sites compose via `composeErrorNotice(context, intro:, tag:, error:)` and log
  `logger.warn('<TAG> ...', e, st)` with the same tag prefix, BEFORE any `mounted` guard.
- **Files are UTF-8 without a BOM.**

## Deliberate deviations from the program spec

Record these in the close-out; do not "fix" them back.

| Spec says | We ship | Why |
| --- | --- | --- |
| `searchClients` gains an `includeArchived` flag | `searchClients` **always excludes archived**; the Archived view is a separate bounded `fetchArchivedClients()` matched locally through `ClientSearchPolicy.matchesClient` | Both stated consumers (clients list, appointment picker) want archived hidden, so the flag would ship with no call site passing `true` — dead config, exactly what P2 deviation #1 removed. The Archived list is bounded (≤ `serverReadLimit`) and reuses the repository's already-cached scan window, so it costs zero extra reads inside the TTL. |

The window is the same one search already reads. |

**On change 6:** an earlier proposal had Residential swap the single name field for First + Last.
Rejected by the owner in favour of showing all three always. That is also the safer shape —
`name` is the field the clients list orders by and Firestore **excludes docs missing the orderBy
field**, so the required top field must never be the one a chip can hide.

### Why change 3 matters more than it looks

The design handoff drew New client as pure fast capture — one address line and nothing else.
That is right when you add a client from the Clients tab, but **the same sheet opens from the
appointment form** when an admin types a client name that doesn't exist yet
(`InlineAddClientHost` → `showAddClientSheet`). On that path the booking needs a real, split
address. Reusing `ClientAddressSection` wholesale is what keeps the inline-add path behaving
exactly as it does today. The `noFixedAddress` toggle is the escape hatch that makes a required
address fair, which is why both travel together.

### Resolved 2026-08-01 — both decided, nothing blocked

**Mobile numbers already on file → consolidate into `phone` on save.** Dropping the field from
the form does not delete the stored value: `copyWith` preserves it, so without this it would sit
on the doc forever — invisible, uneditable, still matched by `matchClientDocs` (which reads
`mobile`) and still in the Wave payload. The decided behaviour, applied in the Edit sheet's
`_save` **before** building the record:

```dart
// Owner decision 2026-08-01. `mobile` is no longer an editable field, so a
// stored value must not be stranded: promote it when there is no phone, drop it
// when there is. Runs on every save, so the fleet self-heals as clients are
// edited — there is no migration script and none is needed.
final typedPhone = _phoneController.text.trim();
final storedMobile = widget.client.mobile.trim();
final resolvedPhone = typedPhone.isNotEmpty ? typedPhone : storedMobile;
```

then `copyWith(phone: resolvedPhone, mobile: '')`.

Pin it with three tests in `edit_client_sheet_test.dart`, one per row of the decision:
mobile-only → phone becomes the mobile and mobile clears; both set → phone kept, mobile cleared;
phone-only → unchanged.

**New client does NOT get the additional-contacts editor** — Edit sheet only. New stays one fast
screen; extra contacts are added on the next edit. `AdditionalContactsSection`,
`additionalContacts` and `disposeAdditionalContacts()` therefore appear in Task 8 only, and Task
6's sheet passes `additionalContacts: const []` to the validator (as its code already does).

```dart
import 'package:scheduling/l10n/l10n.dart';

/// What kind of customer this is. Stored as [raw]; an empty string means the
/// admin never picked one, which is a normal state and not an error.
enum ClientType {
  unset(''),
  residential('residential'),
  commercial('commercial'),
  propertyManagement('property_mgmt');

  const ClientType(this.raw);

  /// The value stored on the Firestore doc.
  final String raw;

  /// Unknown and legacy values fall back to [unset] — mirrors `UserStatus.fromRaw`.
  static ClientType fromRaw(String? value) {
    final trimmed = (value ?? '').trim();
    for (final type in ClientType.values) {
      if (type.raw == trimmed) return type;
    }
    return ClientType.unset;
  }

  /// The three pickable types, in the order the chips render.
  static const List<ClientType> pickable = [
    ClientType.residential,
    ClientType.commercial,
    ClientType.propertyManagement,
  ];
}

/// Localized chip label (mirrors `jobTemplateLabel`).
String clientTypeLabel(AppLocalizations l10n, ClientType type) => switch (type) {
  ClientType.unset => '',
  ClientType.residential => l10n.clients_typeResidential,
  ClientType.commercial => l10n.clients_typeCommercial,
  ClientType.propertyManagement => l10n.clients_typePropertyManagement,
};
```

**Files:**

**Interfaces:**

- Produces: `class ClientPage { List<ClientRecord> items; int rawCount; ClientRecord? cursor; }`
- Produces: `ClientsRepository.fetchClientsPage({required int limit, ClientRecord? after})`
  now returns `Future<ClientPage>` — **breaking**; the only caller is `ClientsListView`
  (Task 3) and the dashboard does not use it.
- Produces: `ClientsRepository.fetchArchivedClients() → Future<List<ClientRecord>>`.
- Produces: `matchClientDocs` skips archived docs.

**The bug this task exists to prevent:** `ClientsListView.getNextPageKey` treats a page shorter
than `_pageSize` as end-of-list. Filtering archived docs out of a page makes it short, so one
archived client would permanently truncate the list below it. The page object keeps the RAW
count and the RAW cursor so neither the stop-condition nor the cursor sees the filtering.

```dart
  Future<ClientPage> fetchClientsPage({
    required int limit,
    ClientRecord? after,
  }) async {
    // Ordered alphabetically by name (with doc id as tiebreaker) to avoid
    // skipping/duplicating clients with shared names.
    var query = _clients.orderBy('name').orderBy(FieldPath.documentId);
    if (after != null) {
      query = query.startAfter([
        _pageBoundaryNames[after.id] ?? after.name,
        after.id,
      ]);
    }
    final snapshot = await query.limit(limit).get();
    final docs = snapshot.docs;
    if (docs.isEmpty) return const ClientPage.empty();

    final last = docs.last;
    // The cursor is the last RAW doc, archived or not — the boundary name map has
    // to key off the same doc the next startAfter uses.
    _pageBoundaryNames[last.id] = (last.data()['name'] ?? '').toString();

    return ClientPage(
      items: [
        for (final doc in docs)
          if (!_isArchived(doc.data())) ClientRecord.fromMap(doc.id, doc.data()),
      ],
      rawCount: docs.length,
      cursor: ClientRecord.fromMap(last.id, last.data()),
    );
  }

    final window = await _clientScanWindow();

      for (final doc in window.docs)
        if (_isArchived(doc.data)) ClientRecord.fromMap(doc.id, doc.data),
    ]..sort(
      (a, b) =>
          a.displayName.toLowerCase().compareTo(b.displayName.toLowerCase()),
```

```dart
  // NOT items.length: filtering archived docs out shortens a page that was full,
  // which would otherwise stop paging and hide every client below it.
  final Map<int, int> _rawPageCounts = {};

  // The last RAW doc of the last page — archived or not. Paging from the last
  // VISIBLE item would skip back over the archived docs each time.
  ClientRecord? _rawCursor;

  late final PagingController<int, ClientRecord> _pagingController =
      PagingController<int, ClientRecord>(
        getNextPageKey: (state) {
          final pages = state.pages;
          if (pages == null) return 1;
          final lastKey = state.keys?.last ?? 0;
          final rawCount = _rawPageCounts[lastKey];
          if (rawCount == null || rawCount < _pageSize) return null;
          return lastKey + 1;
        },
        fetchPage: _fetchPage,
      );

  Future<List<ClientRecord>> _fetchPage(int pageKey) async {
    try {
      if (pageKey == 1) {
        _rawPageCounts.clear();
        _rawCursor = null;
      }
      final page = await ref
          .read(clientsRepositoryProvider)
          .fetchClientsPage(after: _rawCursor, limit: _pageSize);
      _rawPageCounts[pageKey] = page.rawCount;
      _rawCursor = page.cursor ?? _rawCursor;
      return page.items;
    } catch (e, st) {
      ref.read(loggerProvider).warn('CLI-LIST clients page fetch error', e, st);
      rethrow;
    }
```

```js
"use strict";

/**
 * @fileoverview Maintains the denormalized `jobCount` on client docs.
 *
 * The count is recomputed with a Firestore `count()` aggregate and written
 * ABSOLUTELY — never `FieldValue.increment`. This trigger runs with
 * `retry: true`, and a retried event would double-count an increment; an
 * absolute write is idempotent by construction. Same principle as
 * `propagateClientEdits`.
 *
 * Cost is ~1 aggregate read per appointment write that creates, deletes or
 * reassigns a job. Backfill is lazy: a client's count self-heals on its next
 * appointment write, and a row renders no count until the field exists.
 *
 * @module client_job_count
 */

const {onDocumentWritten} = require("firebase-functions/v2/firestore");
const logger = require("firebase-functions/logger");

/** Firestore `NOT_FOUND` — the client was deleted out from under the job. */
const NOT_FOUND = 5;

/**
 * Reads a doc's `clientId` as a non-empty trimmed string, or "".
 * @param {?Object} data Appointment document fields, or null.
 * @return {string}
 */
function clientIdOf(data) {
  if (!data) return "";
  const raw = data.clientId;
  return typeof raw === "string" ? raw.trim() : "";
}

/**
 * Which client docs need their `jobCount` recomputed after this write.
 *
 * Creates and deletes touch one client; a reassignment touches both. An edit
 * that leaves `clientId` alone touches none, so an ordinary title or time
 * change costs zero reads. Personal jobs carry no `clientId` and are skipped.
 *
 * @param {?Object} beforeData Appointment fields before the write, or null.
 * @param {?Object} afterData Appointment fields after the write, or null.
 * @return {!Array<string>} Deduped client doc ids, possibly empty.
 */
function clientsToRecount(beforeData, afterData) {
  const before = clientIdOf(beforeData);
  const after = clientIdOf(afterData);
  if (before === after) return [];
  const ids = [];
  if (before) ids.push(before);
  if (after) ids.push(after);
  return ids;
}

/**
 * Recomputes and writes `jobCount` for one client.
 * @param {!Object} db Firestore instance.
 * @param {string} clientId Client doc id.
 * @return {!Promise<void>}
 */
async function recountOne(db, clientId) {
  const snapshot = await db
      .collection("appointments")
      .where("clientId", "==", clientId)
      .count()
      .get();
  const jobCount = snapshot.data().count;
  try {
    // update(), not set({merge:true}) — a deleted client must not be
    // resurrected as a stub doc holding nothing but a count.
    await db.collection("clients").doc(clientId).update({jobCount});
  } catch (err) {
    if (err && err.code === NOT_FOUND) return;
    throw err;
  }
}

const recountClientJobs = onDocumentWritten(
    {
      document: "appointments/{appointmentId}",
      region: "us-central1",
      // Safe to retry: every write is an absolute recount.
      retry: true,
    },
    async (event) => {
      const before = event.data && event.data.before;
      const after = event.data && event.data.after;
      const ids = clientsToRecount(
          before && before.exists ? before.data() : null,
          after && after.exists ? after.data() : null,
      );
      if (ids.length === 0) return;

      // eslint-disable-next-line global-require
      const {getFirestore} = require("firebase-admin/firestore");
      const db = getFirestore();
      for (const clientId of ids) {
        try {
          await recountOne(db, clientId);
        } catch (err) {
          logger.error("recountClientJobs failed", {clientId, err});
          throw err;
        }
      }
    },
);

module.exports = {clientsToRecount, recountClientJobs};
```

```markdown
- **Archived clients are filtered in DART, never with a Firestore `where`.** Pre-P3
  and Wave-imported docs have no `archived` field, and Firestore excludes docs
  missing a filter field — a `where('archived', isEqualTo: false)` would hide every
  client that predates the flag. The test is always `!(archived ?? false)`.
  That forces the page shape: **`fetchClientsPage` returns a `ClientPage`
  carrying the RAW server-page size and the RAW cursor** beside the filtered
  items, because `ClientsListView.getNextPageKey` stops paging on a short page —
  one archived doc in a full page would otherwise truncate the list permanently,
  and paging from the last *visible* item would re-walk the archived rows. The
  Archived filter reads `fetchArchivedClients()`, which reuses the repository's
  bounded, cached scan window rather than paginating. `getClientById` stays
  unfiltered — editing an old appointment for an archived client must still
  resolve its name and address. Deliberate deviation from the program spec: there
  is no `includeArchived` flag on `searchClients`, because both consumers (the
  clients list and the appointment client picker) want archived hidden, so it
  would have shipped with no caller passing `true`.
- **`jobCount` is recomputed absolutely, never incremented.** `recountClientJobs`
  (`functions/client_job_count.js`) runs `retry: true`, so a retried event would
  double-count a `FieldValue.increment`; it runs a `count()` aggregate and SETS
  the value. It fires only when `clientId` actually changes (create, delete,
  reassignment) — an ordinary title or time edit costs zero reads — and writes
  with `update()`, not `set({merge: true})`, so a deleted client is never
  resurrected as a count-only stub. The field is function-owned: `toMap` must
  never emit it and `firestore.rules` rejects it on client writes, exactly like
  `wave`. Backfill is lazy — a client's count self-heals on its next appointment
  write, and a row renders nothing (never `0`) until the field exists.
```
